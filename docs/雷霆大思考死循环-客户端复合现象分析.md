# 雷霆大思考跨轮死循环：客户端复合现象分析（2026-09-28 收口）

> **文档性质**：现象归因分析 + 与「思考区空正文」引擎 Bug 的边界划清。对应构建史第五节「雷霆大思考死循环事故与根因三段演进」的**分析性补记**——当夜记录的是实证时序，本文件补入「工具集模式」这一此前未记录的诱发维度与「两类异常」收口框架。
> **结论先行**：雷霆大思考**不是 NInfer 引擎缺陷**，是模型长思考特性、客户端工具集约束、会话序列化丢弃 `reasoning_content`、贫瘠初始上下文**多条件耦合**共同触发的客户端复合现象；只能靠业务层手段规避。

## 一、现象回顾（构建史已载，此处仅定位）

DSH 挂 ninfer 后端跑任务时，连续多轮 `output` 触顶（如 32,768），每轮 `reasoning_content` 吃光输出池、正文 0 字被截断；客户端「继续」回传历史只带 `content`（空），新请求重置思考预算，模型丢失前置思考上下文，从零重开大规模思考，形成跨轮死循环。

构建史已坐实的三段根因演进（22:54–23:22）：① 任务复杂 + xhigh + 输出 32K 全烧思考链；② 用户驳斥「加思考帽」并逻辑排除（见第二节）；③ 真根因在两份日志 `req#2` 输入差异——224K 轮带 23,498 token 任务上下文正常收工，256K 轮仅 3,168 token 裸会话，贫瘠输入 + xhigh + 「继续」驱动从零重建。

## 二、关于「思考预算帽」：伪方案，逻辑即可排除

早期（09-22 晚间）曾提出加思考预算帽作应急手段，经用户逻辑推演**直接驳斥，未上机验证即判定无效**：

1. 发生雷霆思考时，模型任务**本身并未思考完成**；
2. DSH「继续」发起**全新请求**，思考预算被重置；
3. 预算帽仅单请求硬截断，强行切断只产出思考不充分的半成品，下一轮重新开启大规模思考，死循环依旧。

> 预算帽只治单请求表象，不能解决跨会话失忆带来的根源矛盾，属治标不治本的伪修复。引擎仓根目录现存的 `起服-长文档档k8v4-256K-MTP-思考预算TBK.bat`（TBK = 思考预算）即该参数化的可选档——仅单请求截断，非根治手段，勿与「已修复」混淆。

## 三、工具集模式：被遗漏的关键诱发维度（观察性分析）

构建史三段演进聚焦「贫瘠输入 + xhigh + 继续失忆」，但未记录 **DSH 工具集模式**对触发概率的放大作用——这是本文件补入的新维度。

观测逻辑：大模型一旦能收敛到「调取工具」，即可通过工具调用把思考成果**落盘**，形成思维接续、终止纯思考推演。DSH 两种模式给出的工具收敛出口差异巨大：

- **简洁模式：仅开放极少工具（典型 2 个）**。模型推演至希望借工具调用落盘思考成果时，环顾可用工具集，**手上没有合适工具可调用**；缺少收敛出口，思考无法落地，只能持续停留在 `reasoning` 区反复咀嚼任务，极易把输出 token 池吃光。本项目中简洁模式雷霆思考触发频率显著高于经典模式，与此直接相关。
- **经典模式：开放一整套丰富工具集**。思考推进到合适节点，模型可随手挑选匹配工具调用；**工具调用成为长思考的收敛出口**，思考链条借工具调用实现阶段性落盘，终止无休止的纯思考推演，超长 thinking 占用显著减少。

> 关键点：不是模型「笨」，是**环境给的工具集合约束了它的收敛出口**。简洁模式缺少可承接思考结果的工具，会显著拉高超长雷霆思考的触发概率。本维度为基于现象的观察性推论，尚未做受控对照实验，记为【分析】。

## 四、完整归因：多条件耦合的复合现象

并非单一引擎 bug 或单纯模型缺陷，需多条件同时凑齐才爆发：

1. **模型侧内在特性**：xhigh 高思考强度下，复杂任务倾向做大规模、长链条内部推演；
2. **客户端环境条件**：
   - DSH 简洁模式可用工具极少，缺少思考收敛的工具出口；
   - 「继续」按钮的会话序列化逻辑：丢弃 `reasoning_content` 思考内容、仅保存正文 `content`，造成跨轮上下文失忆，新请求重置思考预算；
3. **输入上下文条件**：裸 / 贫瘠初始上下文，缺少任务前置材料，模型需从零完整推导整个复杂任务。

> 上面三类因素叠加才触发雷霆大思考死循环；单独某一项，往往不一定复现该现象。

## 五、与「思考区空正文」引擎 Bug 的边界（务必保留区分）

| 维度 | 长思考空收尾（引擎单请求 Bug） | 雷霆大思考死循环（客户端复合现象） |
|---|---|---|
| 发生层级 | 同一个请求内部 | 跨多轮请求 |
| 根因 | `frontend.cpp` 仅在思考 token 恰好用满预算时才强制切正文，思考未到预算时模型 stop 即直接收尾、无正文兜底 | 模型特性 + 工具集约束 + 会话序列化丢 `reasoning_content` + 贫瘠上下文，多条件耦合 |
| 引擎是否有缺陷 | **是**（已修复，方案 C，commit `145bccb`） | **否** |
| 思考预算帽 | 无关 | 伪方案，逻辑可排除 |
| 处理手段 | 引擎源码修复（强制注入「思考结束控制」进正文区） | 业务层规避（换经典模式 / 补上下文 / 避免直接点「继续」） |

> 两者根因、层级、处理手段完全不同，排查时长思考异常**先定性再下手**，勿混为一谈。详细引擎侧分析见 `docs/ninfer-思考区空正文问题与治本方案-20260927.md`。

## 六、规避手段（业务层，引擎不可解）

- **避免直接点「继续」**：将完整思考内容 + 已有输出片段一同重新投喂上下文，或新建完整会话；
- **优先使用工具集完备的经典模式**，降低触发概率（尤其长任务）；
- **补全任务前置上下文**，避免贫瘠裸输入从头推导；
- 上述为规避而非根治；根治需客户端在「继续」时保留 `reasoning_content` 或提供思考续接机制（超出本引擎范畴）。
